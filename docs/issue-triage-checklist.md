# Issue Triage Checklist

Use this checklist before starting work on an issue or closing it as complete.

## 1. Clarify the problem

- What user-visible problem is being reported?
- What is the expected behavior?
- What evidence or reproduction steps are available?

## 2. Define the implementation scope

- What is the smallest useful change?
- Which files or docs are likely affected?
- Are there any related risks or assumptions?

## 3. Validate before closing

- What changed?
- How was it checked?
- Does the result address the original issue?

## 4. Close the loop

When opening a pull request, link the issue and include the validation notes so the issue can be closed confidently.
